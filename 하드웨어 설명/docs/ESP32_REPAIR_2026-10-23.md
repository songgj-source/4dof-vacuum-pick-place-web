# ESP32 교체 후 펌프 펌웨어 (Pi를 거쳐 올림)

대상 보드: ESP32-D0WD-V3 (revision v3.1), MAC 70:b8:f6:70:3d:3c, 플래시 4MB, CP2102 `_0001`.
10-16 보드(MAC d0:ef:76:47:56:c0)를 바꾼 새 보드다. 새 보드는 펌프 식별 명령(`q`)에 답하지 않았다.

로봇 위 Raspberry Pi에 꽂힌 그대로 올렸다(노트북 → Wi-Fi → Pi → USB → ESP32). 팀 환경은 건드리지 않았다.
- 도구: Pi의 우리 가상환경(`~/4dof_ik_pi_test/.venv`)에 esptool 5.6.0 설치.
- 포트: 펌프 포트 이름 `/dev/serial/by-path/platform-fd500000.pcie-pci-0000:01:00.0-usb-0:1.3.2:1.0-port0`에만 올렸다.
  같은 CP2102 `_0001`인 라이다(포트 1-1.2)에는 올리지 않았다. 쓰기 전에 `flash-id`로 칩과 MAC을 확인했다.
- 백업: 기존 4MB 플래시 전체를 `output/esp32_repair/20261023_70b8f6703d3c/original_flash.bin`에 보존했다.
  Pi와 노트북 양쪽에 두었고, SHA256은 `cad4ebdd4ef45d17b5e948c9a0b7dca6eed89ba0b43881a74550b2e1cd6e1f59`이다.
- 펌웨어: `firmware/esp32_vacuum/esp32_vacuum.ino`를 노트북에서 arduino-cli 1.5.1과 esp32 코어 3.3.11로 컴파일했다(`esp32:esp32:esp32`, 20%).
- 업로드:
  `esptool --chip esp32 --baud 460800 write-flash -z --flash-mode keep --flash-freq keep --flash-size keep 0x1000 bootloader 0x8000 partitions 0xe000 boot_app0 0x10000 app`.
  네 영역 모두 "Hash of data verified".
- 확인:
  - `q`에 `ESP32_VACUUM_L9110S GPIO26/25`로 답했다.
  - `s`에 `[동작] 정지 (Stop)`로 답했다.
  - `find_pump_port.py --check` 결과는 펌프 응답 OK였다.
  - 흡착(`p`)과 실제 펌프 구동은 이번에 시험하지 않았다.

다시 올릴 때도 같은 방법을 쓴다. 다만 포트 위치 이름이 바뀌었을 수 있으니, `python scripts/find_pump_port.py`나 `flash-id`로 펌프 ESP32인지 먼저 확인한다.
